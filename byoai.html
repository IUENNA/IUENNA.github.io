Connect IUENNA to your AI

IUENNA exposes one canonical MCP access path: a public, read-only Remote MCP using Streamable HTTP. No local server, Python installation, Node setup, project-specific API key, or authentication is required.

IUENNA Remote MCP endpoint
https://iuenna-mcp.dominik-hagmann13.workers.dev/mcp

In any compatible AI client, add this URL as a custom Remote MCP server. The service is stateless and reads only public IUENNA research data.

Data architecture: ARCHE remains the authoritative long-term repository. IUENNA's full corpus and graph remain the canonical machine-readable layers on GitHub Pages. The Remote MCP uses compact, reproducibly generated query projections only for efficient retrieval; these projections are non-authoritative and disposable.

Available MCP tools

ToolPurpose
search_iuenna_corpusSearch the complete 20,355-file primary-resource corpus.
get_findspot_detailsRetrieve findspot metadata and associated curated datasets.
get_related_resourcesResolve a place, dataset, collection, or publication and return related archived files and entities.
get_graph_neighborhoodTraverse the semantic graph around an indexed node, with optional predicate and direction filtering.
get_geodata_catalogList the 9 curated archaeological GeoPackages.
get_corpus_statisticsReturn collection-level repository metrics plus explicitly separate primary-resource-corpus metadata.
get_project_bibliographyQuery the public IUENNA Zotero library.
Counts: the ARCHE collection statistic total_items is a collection-wide repository item/entity count. It is not the primary-file count. The canonical primary-resource corpus contains 20,355 archived files.

Provenance, citation and rights

ARCHE is the authoritative long-term repository. The top-level IUENNA collection is persistently identified by 21.11115/0000-0016-7B39-F.

Access and reuse: open discovery metadata does not mean that every archived binary resource is openly downloadable or licensed identically. Inspect the metadata, rights statement and access conditions of the specific ARCHE record before reuse.

When using a specific dataset, document, image, GeoPackage, or other archived resource, cite its individual ARCHE PID and metadata rather than only the project homepage.
